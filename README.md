# Mera Haq on UMANG (मेरा हक)

**Profile-first discovery of Indian government schemes, backed by evidence-checked official data.**

Answer three questions (age, gender, State/UT). Mera Haq checks your answers against eligibility rules quoted word for word from official government sources, explains each result, and sends you to the official portal to apply. It never submits applications and never sends your answers anywhere.

- Live (GitHub Pages, from `main`): https://devneeraj15.github.io/Mera-Haq/
- Concept deck and brief (describe the earlier prototype concept): [`Mera_Haq_Proactive_Entitlement_Discovery.pptx`](./Mera_Haq_Proactive_Entitlement_Discovery.pptx), [`.pdf`](./Mera_Haq_Proactive_Entitlement_Discovery.pdf), [`SUBMISSION.md`](./SUBMISSION.md)

> **Prototype notice.** This is not an official Government of India service. Scheme information comes from official sources and is linked on every scheme page. Always confirm eligibility and deadlines on the official portal.

## What's in the dataset (honestly)

Current coverage: **66 schemes**, 11 Central and 55 Maharashtra (MahaDBT). **No State/UT-specific schemes have been ingested yet for the other 27 States and 8 UTs**; users there see Central schemes only. myScheme's Terms of Use prohibit scrapers, india.gov.in blocks automated access, and data.gov.in disallows crawling, so nationwide coverage needs an authorised data feed. Details: [DATA_QUALITY_REPORT.md](./DATA_QUALITY_REPORT.md) and [DATA_SOURCE_INVENTORY.md](./DATA_SOURCE_INVENTORY.md).

Every eligibility rule, benefit and document in `data/schemes.json` carries the exact sentence it came from. The validator re-finds each sentence in a stored snapshot of the official page (978 / 978 found in the current build).

## Features

- **Overview dashboard**: counts of schemes offered in your location and your likely and potential matches; profile completion; deadlines and official notices (only those actually published in sources).
- **Find Schemes**: search, category / government-level / verification / result filters, pagination. Filter state lives in the URL, so back, forward and refresh work.
- **My Eligible Schemes**: 10–20 results first, then progressive questions ranked by how many results they would change.
- **Scheme detail**: conditions met, not met, unknown and to confirm yourself, each with its source quote; benefits; documents; how to apply; official sources with capture dates; verification status.
- **Saved Schemes** and a **Documents Checklist** (ticks only, no uploads).
- **Government Resources** (official portals, per-State/UT coverage table) and **Help, FAQs and Privacy** (including "Delete all my data").
- **Open Data API (proposal)**: the app reads data only through a proposed Open Government Schemes API (OpenAPI 3.1, [`docs/api/openapi.yaml`](./docs/api/openapi.yaml)), served statically at `api/v1/`. Pointing `<meta name="merahaq-api-base">` at an official endpoint switches the data source.

## Proposal to government

Scraping myScheme is not permitted, so the path to national coverage is for government to adopt this. [`docs/PROPOSAL.md`](./docs/PROPOSAL.md) sets out two options: (A) integrate Mera Haq into UMANG, or (B) publish an open, read-only Schemes API. It covers governance, privacy (DPDP Act), a phased roadmap and the specific asks. A matching pitch deck accompanies it.

Eligibility outcomes: `LIKELY_ELIGIBLE`, `POTENTIAL_MATCH`, `NOT_ELIGIBLE`, `INSUFFICIENT_INFORMATION`, `SCHEME_NOT_CURRENTLY_OPEN`, `NEEDS_MANUAL_VERIFICATION`. They are decided by a deterministic rule engine with no AI. See [ARCHITECTURE.md](./ARCHITECTURE.md).

## Running locally

Requirements: Node.js ≥ 20, Python ≥ 3.10.

```bash
npm ci
```

```bash
python -m pip install -r scripts/requirements.txt
```

```bash
npm run build
```

```bash
npm run serve
```

Then open http://127.0.0.1:4173/. Opening `index.html` from the file system does not work, because the dataset is loaded with `fetch`.

## Testing

```bash
npm test
```

```bash
npm run dryrun
```

```bash
npx playwright test
```

`npm test` runs the engine and pipeline unit tests. `npm run dryrun` runs the real-data dry run (personas × real schemes, oracle check). `npx playwright test` runs the end-to-end suite on installed Chrome (`PW_CHANNEL=msedge` to use Edge). Results: [TEST_REPORT.md](./TEST_REPORT.md).

## Updating scheme data

```bash
npm run data:offline
```

```bash
npm run data:sync
```

`data:offline` rebuilds from the stored snapshots (no network). `data:sync` re-fetches official sources (throttled, robots.txt-respecting), then normalises, validates, syncs and regenerates reports. Check `data/reports/review-queue.json` and `data/history/` before committing. A failed fetch never replaces a previously verified record.

## Environment variables

| Variable | Used by | Purpose |
|---|---|---|
| `PORT` | `scripts/serve.mjs` | Dev server port (default 4173) |
| `PW_CHANNEL` | Playwright | Browser channel: `chrome` (default), `msedge`, `chromium` |
| `DRYRUN_DATE` | `scripts/dry-run.mjs` | Evaluation date for the dry run (default 2026-11-06) |
| `DATA_GOV_IN_API_KEY` | reserved | Future data.gov.in connector. **Not used yet**, and never exposed to the frontend |

The frontend uses no secrets and has none to leak. `.env*` files are git-ignored.

## Deployment

The site is static. GitHub Pages serves the repository root: after merging to `main`, run `npm run build` and commit `app.js` and `index.html` (the build stamps cache-busting hashes). Hash routing makes refresh and deep links work without server rewrites, and `404.html` sends unknown paths to the in-app 404.

GitHub Pages cannot send HTTP security headers, so the CSP is set through `<meta>`. On Netlify or Cloudflare Pages, `_headers` adds HSTS, `frame-ancestors`, `Permissions-Policy` and the rest. See [SECURITY_AUDIT.md](./SECURITY_AUDIT.md).

CI (`.github/workflows/ci.yml`) runs on every push and PR: dependency audit, offline data rebuild, unit and pipeline tests, dry run (fails on oracle mismatch), build and E2E.
